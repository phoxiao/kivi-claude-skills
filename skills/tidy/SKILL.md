# tidy — 目录整理标准流程

对 `$ARGUMENTS` 指定的目录执行整理。没给路径时先问。这套流程源自 2026-07 全盘整理工程的实战经验，核心纪律：**先看全貌再动手、删除前必验证、移动可以大胆、删除必须暂存**。

## 第 0 步：环境判断（每次必做）

- `mount | grep <卷>` 看文件系统：FUSE 挂载会产生 `.fuse_hidden*` 残影（句柄释放后自动消失，不要强删）；`noowners` 卷不能当 Photos 系统图库。
- 目录在 iCloud 同步范围（~/Desktop、~/Documents）时：`ls -lO` 查 `dataless` 标记——占位文件 Finder 拒删，需先 `brctl download` 拉回本体；删除会同步到用户所有 Mac，必须提醒。
- 查目录内是否已有 `_taxonomy.md` / `_索引.md`：**已有组织是有意为之**，扩展它，不要推倒。

## 第 1 步：侦察（只读，不动任何文件）

1. 规模与构成：顶层逐项列（目录带文件数+大小，文件带大小）；扩展名分布 `find -type f | sed 's/.*\.//' | sort | uniq -c | sort -rn`。
2. 年龄分布：每个子目录的最后活跃时间 `find -exec stat -f %m` 取最新——多年未动的大块头是清理重点。
3. 大文件普查：`find -size +50M`，逐个判断性质（安装包/数据转储/录屏/文档）。
4. **不要相信目录名，抽样看内容**：叫 Software 的可能装着审计报告，叫 ok.zip 的可能是相册，叫 Books 的可能混着工作文档。zip/rar 先 `unzip -l` 看内容再定去向。

## 第 2 步：分类去向（语义优先，复用既有体系）

本机的既定归宿（三区模型，先查记忆文件 file-organization-scheme.md 获取最新状态）：

| 内容 | 去向 |
|---|---|
| 电子书 epub/书籍 pdf | `/Volumes/BOX/Books/`（成套的保持目录完整） |
| 论文（arXiv 编号 `NNNN.NNNNN` 或英文学术标题） | `/Volumes/BOX/技术资料/11-论文与学术资料/` |
| 技术资料/文章 | `/Volumes/BOX/技术资料/01-12` 按主题；拿不准进 `00-未分类-*` |
| 课程/教程 | `/Volumes/BOX/课程/` |
| 照片视频 | `/Volumes/BOX/照片/YYYY-MM 事件名/`（EXIF 定名见第 4 步） |
| 工作文档（结项） | `/Volumes/BOX/工作档案/`——10-项目(拼音前缀-项目名)/20-产品/30-技术/40-售前市场/50-管理团队/60-演示汇报/70-资料库/90-待整理 |
| 活跃工作/个人文档 | iCloud `~/Documents/Work/<项目>/`、`~/Documents/Personal/` |
| 安装包 dmg/pkg/iso、公开可再下载的软件压缩包 | 待删（装完即删原则） |
| 运行时/工具发行版 | `/Volumes/BOX/Applications/` |
| 项目代码包（README+代码+数据成套） | 保持整体，勿按类型拆散 |

规则：按语义不按格式；一次移动一批同类；目录深度 ≤3；同名冲突加 ` (2)` 后缀，禁止覆盖。

## 第 3 步：去重（删除的唯一合法理由是「验证过的重复」）

1. 同大小分桶 → 桶内逐对 MD5。大目录用 Python 脚本 + MD5 缓存 json（可断点续跑），放后台执行。
2. 两目录疑似互为副本时：先「文件数+总字节」粗比，一致再抽样 MD5，删除前跑一次**无缓存的独立复核**（分层抽样+全部大文件）。
3. **合法的重复不删**：软件发行版内部的重复 jar、`.svn/pristine`、`.git` 对象、快照目录的内部结构。
4. 损坏压缩包：逐条目尝试解压，能解出的逐一 MD5 对照正本，全部有对应才可删。

## 第 4 步：照片特殊处理

- 用内置 `sips -g creation` 读 EXIF 拍摄时间（无需装工具），每目录抽 20 张取众数得 `YYYY-MM`；跨度 >3 个月用 `YYYY-MM~YYYY-MM`。
- 无 EXIF（livp/截图/微信图）退回文件名内嵌日期或 mtime，标注估算。
- 目录名统一 `YYYY-MM 事件名`；定不出事件名的用 `YYYY-MM 待命名-原名` 保留线索。

## 第 5 步：执行纪律

- **移动**：盘内 mv 直接做；跨盘先拷后核（大小/数量）再删源；超过 ~20 项的移动先给用户看清单要确认。
- **删除**：一律先 `mv` 进 `<卷根>/.待删-YYYYMMDD/`，最后把 `rm -rf <暂存目录>` 命令交给用户执行。自动模式下批量 rm/osascript 删除常被安全分类器拦——不要反复硬试，暂存+用户一键是标准通路。
- Finder 废纸篓路线备用：写 .applescript 文件后 `osascript` 执行（比 -e 内联通过率高）；iCloud dataless 文件 Finder 拒删。
- 预计超过 2 分钟的命令一律 `run_in_background` + 落盘日志 + 可续跑设计。

## 第 6 步：收尾

1. 目录根写/更新 `_索引.md`：每类一行说明 + 速查表（“找 X → 去 Y”）。
2. 报告：移动了什么去哪、暂存了什么为什么、哪些没动及原因、遗留决定点。
3. 更新记忆文件 file-organization-scheme.md 的状态。

## 状态协议（整合版核心，所有调用方式共用）

状态中枢在 `~/.file-org/`：`state.json`（决策队列 + 三区指标 + last_run）、`journal.log`（追加式操作台账，格式 `时间 | 执行者 | 动作 | 详情`）。

**无参数调用 `/tidy` = 拍板模式**：
1. 读 `state.json`，取 `status=open` 的队列条目。
2. 呈现方式分双层：桌面 App 会话先渲染 widget 面板总览（按钮 sendPrompt），随后不论何种载体都用 **AskUserQuestion 逐条抛选择题**（这是全载体可靠内核：终端、手机 tmux 同样可用）。每题的 options 直接来自条目的 `options` 字段。
3. 用户选定即执行对应动作，条目改 `status=done`（附 `resolved` 时间与选择），写 journal。
4. 全部处理完输出一行总结；队列清零时说明系统健康。

**带路径调用 = 整理模式**（原流程第 0-6 步），额外要求：
- 启动时读 state.json 了解全局；产生的「判断题」不再只写进报告文本，同时 append 到 queue（带 evidence 和 options）。
- 所有移动/暂存操作逐条写 journal。
- 收尾更新 `zones` 指标与 `updated` 时间戳。

**自动任务写入约定**（守门/体检脚本同样遵守）：只允许 append queue 和 journal、更新 zones/last_run；绝不改动 `status=open` 条目的内容；queue 条目 id 用 `q<时间戳>` 避免冲突。

**并发锁（多实例防撞，实测踩过：两个 /tidy 会话同时整理同一区域）**：整理模式开工前 `mkdir ~/.file-org/.tidy.lock`——成功则写入 `$$ 与目标路径` 到锁目录内 info 文件；失败说明另一实例在跑，读出对方信息告知用户并停止，绝不并行操作重叠目录。收尾（含异常收尾）必须 `rm -rf` 该锁。拍板模式只读队列可不加锁，但改写 state.json 前用「读-改-写尽量原子（临时文件+mv）」。暂存目录一律带日期（.待删N-YYYYMMDD），发现暂存区里有本实例未创建的条目时：不删、不动、报告用户。

## 已知坑速查

- 批量 rm 被分类器拦 → 暂存目录 + 用户执行；不要绕。
- iCloud「优化存储」的 dataless 文件：Finder 删除报「需要下载」，`brctl download` 拉回后再删，或 rm 占位文件（30 天可从 iCloud 恢复）。
- 双机差异：Downloads 不走 iCloud 各机独立；桌面/文稿双机同步，删除两边生效。
- `~/Pictures`、`~/Library/Mobile Documents`、废纸篓受 TCC 保护写不进/读不了，临时文件用主目录下的普通目录。
- APFS 大小写不敏感：`PPT` 和 `ppt` 是同一目录。
