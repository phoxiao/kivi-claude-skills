# 证据层与三级笔记：操作细则

SKILL.md 第 1、2 步的展开。读这份文件的时机：正要开始建 evidence.md，或者归纳时拿不准某条该不该升到 L1。

## 一、证据层：抽什么、不抽什么

原则：**证据层不是全文压缩，是"后面会用到的原话"的索引。** 判断标准是——如果这条不在，后面某个论点就没法证明是作者说的。

### 值得抽

- 作者的核心断言原话（尤其是反直觉的、会被引用的那几句）
- 所有数字、时间、比例，连同作者给的来源（或明确记录"未给来源"）
- 支撑论点的具体案例、演示、故事——这些是 L2 论证强度评级的依据
- 定义。作者对一个词的定义和通用定义不同时，必须抽，否则后面整段推理会读歪
- 作者自己承认的局限、例外、"当然这不适用于……"——这些是第 3 步张力边的主要来源，最容易被摘要丢掉

### 不值得抽

- 过渡句、寒暄、听众互动
- 已经在别处抽过的同义重复（作者常把一个观点说三遍）
- 与用户第 0 步目的完全无关的支线（记一条"此处有关于 X 的一段，未展开"即可）

### 密度参考

一小时演讲 30–60 条，一篇论文 20–40 条，一本书按章节分文件、每章 15–30 条。超过这个量级通常是在抄原文，回去砍。

### 编号规则

- 全局连续 `E1, E2, ...`，跨文件不重置。编号一旦分配就不改——后面的笔记引用了它。
- 需要补录时用 `E7a`，不要重排后面所有编号。
- 分章节的长材料可以用 `E3-12`（第 3 章第 12 条）。

### 定位标记

按材料形态选一种，全程统一：

| 形态 | 标记 | 注意 |
|---|---|---|
| 视频/音频 | `12:30` | 用转录里真实的时间戳；转录没时间戳就改用段落序号，不要估算 |
| PDF/书 | `p.14` | 用页面上印的页码，不是 PDF 阅读器的第几页——两者常差几页 |
| 网页/纯文本 | `§4` 或 `¶27` | 章节号优先，没有小标题才用段落序号 |
| 用户粘贴 | `¶N` | 从粘贴内容的第一段开始数 |

**编造定位是这个 skill 最严重的失败。** 它让整套可追溯机制变成装饰，而且用户第一次查证失败就再也不会信任任何一条笔记。拿不准就写 `[位置不明]`，丑但诚实。

## 二、标记类型的边界判定

分不清时按这个顺序问：

1. 有数字吗 → `DATA`
2. 是具体发生过的事、可复述的案例吗 → `EXAMPLE`
3. 是"世界是这样的"且原则上可核查吗 → `FACT`
4. 是"我认为/我预测/我们应该"吗 → `OPINION`
5. 其余的断言 → `CLAIM`

`FACT` 和 `CLAIM` 的区别最实用：`FACT` 值得花一次 WebSearch 去核，`CLAIM` 不值得（核了也只能得出"这是作者的看法"）。

### ⚠️ 标注

发现下面三种情况，在该条证据后面加一行 `⚠️` 说明：

- 与材料内另一条证据矛盾 → `⚠️ 与 E23 矛盾：那里说的是……`
- 数据没有来源，且该数据支撑着一个重要结论 → `⚠️ 无来源，但 L2-3 整段依赖它`
- 外部核查发现不符 → `⚠️ 核查：实际是 X（来源），作者说的 Y 可能是旧数据`

**不要把 ⚠️ 直接改进原文引用里。** 引用永远是作者说的原话，你的判断放在下面单独一行。混在一起以后没人分得清哪句是谁说的。

## 三、L2：从证据归纳论证单元

一个 L2 单元 = 一个论点 + 支撑证据 + 强度评级 + （可选）你的判断。

```markdown
### L2-4 提示词应该像代码一样被工程化管理

作者认为，既然自然语言现在承担了程序的角色，围绕代码建立的那套实践（版本控制、
测试、复用、code review）应该原样搬到提示词上。

支撑：E7（Software 3.0 的定义）、E12（他自己团队的提示词仓库）、E15（回归测试的例子）
强度：**中** —— 类比推理成立，有一个自用案例，但没有任何团队规模的数据。
判断：类比在"版本控制"上很强，在"测试"上弱得多——提示词的输出是分布不是确定值，
      沿用代码的测试范式会失效。这一点作者没处理。（→ 张力边）
```

### 归并的手法

第一遍会归出十几个 L2，太碎。合并的判据不是"主题像"，是：**如果这两条的支撑证据高度重叠，或者其中一条的成立完全依赖另一条，就该合并。**

反过来，一个 L2 挂了超过 8 条证据，通常是它太笼统了，拆开。

### 那句「判断」

不是每条都要写。写的时机是：你发现了作者没说的东西——缺失的前提、失效的边界、和其他来源的冲突。这些是第 3 步张力图的原料，在这里顺手记下来，到画图时就不用重新想。

没有判断就留空。硬写会稀释真正有价值的那两三条。

## 四、L1：主框架

3–7 条。每条一句话，读完这 7 句应该能大致复述材料在讲什么。

三个常见的组织轴，挑最贴合材料的一个，不要混用：

- **演化轴**：按时间/阶段（Software 1.0 → 2.0 → 3.0）
- **论证轴**：按"问题 → 原因 → 方案 → 反驳"
- **主题轴**：并列的几个独立议题（多见于访谈、杂文集）

材料本身结构混乱时（访谈、即兴演讲最常见），**用你归纳的轴，不要照抄原文的出场顺序**——顺序是讲者的即兴，不是逻辑。但要在 notes.md 开头说明一句"本笔记按 X 轴重组，与原文顺序不同"，免得用户对照原文时困惑。

## 五、自检

写完 notes.md 过一遍：

- [ ] 每个具体数字/案例都有 E 编号？（没有的删掉或回原文补）
- [ ] 论证强度不是全"强"？全强说明没在评级，在鼓掌
- [ ] L1 是否覆盖全材料？有没有整章内容没进任何 L1？
- [ ] "作者认为"和"事实是"分开了吗？
- [ ] L1 条数在 3–7 之间？
