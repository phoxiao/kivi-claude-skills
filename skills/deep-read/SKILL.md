# deep-read — 把长材料读到能用

这套流程针对一个具体困境：材料值得读，但太长、太密、或者读完三天就忘。它的产出不是摘要，是**一份能追溯到原文的结构化笔记 + 一次验收过的理解**。

先讲清楚这个 skill 的两条设计原则，后面每一步都是从这两条推出来的：

**原则一：所有归纳必须能反向走回原文。** 摘要生成摘要是幻觉的温床——越往抽象层走，离原文越远，而"具体的例子和数据"恰恰是最容易被顺手编出来的。所以证据层先建，编号固定，后面每个论点都挂编号。用户看到一句可疑的话，两秒能查到出处。

**原则二：理解程度只能由人的卡壳来测量。** 让 AI 生成一遍费曼式解释再自查，等于把体温计放进热水里——AI 不会卡壳，测不出任何东西。所以第 4 步的费曼是反转的：AI 出题，人来讲，AI 对照证据层判定哪里是真懂、哪里只是在复述术语。

## 第 0 步：分诊与定标

**不要默认走完整流程。** 全套跑下来是几十分钟人机互动，对八成的材料是浪费。先花两分钟做三件事：

1. **问用户两个问题**（这两个答案会贯穿后面每一步，缺了它们第 4 步的"个人应用"只能输出通用鸡汤）：
   - 你为什么要读这个？想解决什么问题、验证什么判断？
   - 读完打算拿它干什么？写东西 / 做决策 / 单纯扩展视野？
   
   用户如果说"就随便看看"，那答案本身就说明该走快通道。

2. **扫材料**：体量（字数/时长）、类型（论证型 / 叙事型 / 教程型 / 观点型）、信息密度。抽样读三段而不是读标题——标题和摘要是作者的营销文案。

3. **定档**，把判断和理由一句话告诉用户，让他确认或改档：

| 档 | 什么时候选 | 做哪些步 |
|---|---|---|
| **A 快通道** | 信息密度低、观点型短文、或用户只需知道"讲了什么" | 第 1 步的轻量版 + 一页要点，结束 |
| **B 标准** | 有论证结构、值得记住，但不需要能复述 | 第 1、2、3、5 步 |
| **C 深读** | 要拿它做决策、要写东西引用它、或者是领域基础材料 | 全部五步 |

**为什么要显式定档**：不定档就会默认最贵的做法，用户中途觉得啰嗦就整个放弃，反而什么都没留下。

## 第 1 步：摄入与证据层

这是**唯一直接接触原文的一步**。后面所有步骤都只读证据层，不再回头翻原文——这是原则一的机制保证。

### 拿到全文

| 材料形态 | 做法 |
|---|---|
| 本地 PDF / EPUB / DOCX | `pandoc` 转 markdown；PDF 优先用 Read 工具直接读（保留版面），扫描件才考虑 OCR |
| 网页 / 长文 | WebFetch；正文抓不全时用 dev-browser 打开取文本 |
| 视频 / 播客 | 优先找官方字幕、逐字稿、平台转录。本机**没有** whisper / yt-dlp，不要假装有——直接告诉用户需要他提供转录文本，或者装一个（`brew install yt-dlp`、`uvx mlx-whisper`），别在这里空转 |
| 用户直接粘贴 | 直接用 |

原文超过 ~5 万字时，分段处理并在证据层里保留段落边界，不要试图一次塞进上下文——塞得进也会导致中段内容被稀释。

### 建 evidence.md

逐段过原文，抽出值得记的片段，每条一个固定编号。格式：

```
E7 [CLAIM · 12:30] "Software 3.0 是用自然语言编程，提示词就是程序"
E8 [DATA · p.14] 训练成本从 2020 年的 $4.6M 降到 2024 年的 $0.5M —— 作者未给来源
E9 [EXAMPLE · 18:05] 用 Cursor 写小工具的现场演示，从零到能跑约 90 秒
```

标记类型的意义在于后面分级处理，别省：

- `CLAIM` 作者的断言（可能对可能错，笔记里必须写成"作者认为"）
- `FACT` 声称的客观事实（可外部核查）
- `DATA` 数字、图表
- `EXAMPLE` 具体案例、演示
- `OPINION` 明显的价值判断、预测

**转述准确 ≠ 事实为真，这两件事分开记。** 你的第一职责是准确转述作者说了什么；作者说错了是另一回事，写在 `⚠️` 标注里，不要偷偷"纠正"成你认为对的版本。

**定位标记必须真实**：时间戳、页码、章节号、段落序号，用材料里真实存在的。没有可靠定位（比如用户粘的纯文本）就写段落序号，别编页码——编出来的定位比没有定位更糟，它会骗人。

**核查只做两类**：一是材料内部矛盾（作者前面说 A 后面说非 A），二是关键数据的外部核查（只查决定结论成立与否的那两三个数，用 WebSearch）。不要逐条核查，成本对不上。

## 第 2 步：自下而上做三级笔记

原始框架是 L1→L2→L3 往下写，那个方向会让最需要证据的第三级离原文最远。**反过来做**：证据层（第 1 步产物）就是 L3，从它往上归纳。

- **L2 论证单元**：每个论点一段，列出支撑它的证据编号，然后给一个论证强度评级。
- **L1 主框架**：3–7 个骨架点，覆盖全材料。超过 7 个说明还没归纳完，回去合并。

论证强度评级是这一步的核心增量，原始框架完全没有批判性阅读这一环：

| 评级 | 含义 |
|---|---|
| 强 | 有数据或可验证案例支撑（E 编号里有 DATA/FACT/EXAMPLE） |
| 中 | 有推理链但只有举例，或数据来源不明 |
| 弱 | 只是断言（支撑全是 CLAIM/OPINION），靠作者权威成立 |

写"弱"不是贬低作者——演讲和随笔本来就不承担论文的举证义务。标出来是为了让用户知道**哪些结论可以直接拿去用，哪些还需要自己验证**。这个区分是笔记能不能"能用"的分水岭。

细节见 `references/evidence-and-notes.md`（证据抽取的取舍标准、L2 归并手法、常见误判）。

## 第 3 步：张力图谱

**不要画全景概念图。** 节点一多 Mermaid 就变成没人看的蜘蛛网，而且"层级/因果/支撑"这些边大多是把线性提纲换了个画法，信息增量接近零。

真正值得可视化的是**你的大脑读线性文字时抓不住的东西：矛盾、权衡、成立条件**。所以画三类边，主体是后两类：

- 骨架边（`-->`）：只画 L1 之间的主干，把图撑起来，尽量少
- **张力边**（`-.张力.->`）：作者内部的紧张关系、取舍、"这条成立需要 X 前提"
- **冲突边**（`==冲突==>`）：与用户已有认知、与其他来源、与实际经验冲突的地方

硬约束两条，理由在下面：

1. **节点 ≤ 15**。超了就拆成分层图（一张主干 + 若干局部）。15 个节点是一屏能扫完的上限，超过就失去了"比线性文字更快"的唯一优势。
2. **至少 2 条张力边或冲突边**。找不到通常意味着两种情况之一：还停留在复述层面，或者这份材料确实是平铺直叙的教程型。是后者就直说，跳过这步——但先老实回去找一遍，"没有张力"往往是没读透的症状而不是材料的属性。

Mermaid 语法规范、关系类型的判定、分层拆图的做法见 `references/tension-map.md`。

## 第 4 步：反转费曼（只在 C 档做）

**AI 不代替用户讲。** 详细的出题策略、判定标准、三轮的具体话术见 `references/feynman-inverted.md`，这里只给骨架：

- **R1 盲讲**：从张力边和"看起来像懂了其实只记住了名词"的点里挑 3 个提问，用户口述。AI 对照证据层判定：是真解释了机制，还是把原文的术语换了个说法。
- **R2 追击**：拿 R1 暴露的漏洞和张力边做边界攻击——"这个结论在什么情况下不成立？"。目标不是难倒用户，是找到理解的边界在哪。
- **R3 迁移**：把结论套到第 0 步采集的用户真实场景上，产出具体到能明天就动手的行动，而不是"要多关注 AI 发展"。

**用户不配合是常态，准备好降级路径**（三档都比放弃强）：

1. 用户不想打字 → AI 写一份**含 3 处刻意错误**的解释，请用户抓错。交互成本降到最低，但仍然要求真实理解才能完成。
2. 用户只想看 → 输出一份自测题卡（问题 + 答案分开），存进笔记供以后自测。
3. 用户明确说"跳过" → 跳过，别劝。在笔记里留下题卡就行。

## 第 5 步：落盘

默认写到当前工作目录下的 `deepread/<材料短名>/`。当前目录是代码仓库时先问一句放哪，别往人家项目里塞笔记。

```
deepread/<slug>/
├── README.md        # 入口：一段话讲这是什么 + 3 条最该记住的 + 导航
├── evidence.md      # 证据层（E 编号 + 定位）
├── notes.md         # L1/L2 结构 + 论证强度
├── tension.md       # 张力图 + 每条张力边的说明
└── open.md          # 未解决的问题、待验证的事实、自测题卡
```

`open.md` 是最容易被省掉也最有价值的一份。**三天后回来的人不会重读 notes.md，他会看 open.md**——那里写着上次卡在哪、哪个数字还没核实、哪个结论还没敢用。它是下一次的入口。

README 里的"3 条最该记住的"要写成完整的句子，不是关键词。「Software 3.0」不是一条笔记，「用自然语言写提示词就是在编程，所以提示词该像代码一样版本管理和测试」才是。

## 常见失败模式

- **摘要伪装成笔记**：产出读起来像材料的压缩版，一条张力边都没有，论证强度全是"强"。说明整个过程都在复述，没有任何判断。回到第 2 步重做评级。
- **证据层编号断链**：notes.md 里出现没有 E 编号支撑的具体数字或案例。这几乎一定是生成出来的，删掉或回原文补定位。
- **张力图节点爆炸**：忍不住把所有概念画进去。删到 15 个以内，删掉的东西 notes.md 里都有。
- **在第 0 步偷懒**：没问用户的目的就开始读，最后"个人应用"那节只能写通用建议。这时候补问也来得及，别硬写。
- **为不值得的材料跑全流程**：一篇公众号观点文跑到第 4 步，用户会觉得这个 skill 很烦。分诊那步认真做。
